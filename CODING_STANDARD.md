# Стандарт кодування проєкту PharmacyStock

## 1. Загальні положення

Цей стандарт визначає основні правила написання коду для навчального проєкту PharmacyStock. Проєкт розробляється мовою C# на платформі .NET 8.

Основна мета стандарту полягає в тому, щоб код був зрозумілим, однаково оформленим і зручним для подальшого редагування.

## 2. Іменування

У проєкті використовуються такі правила іменування:

| Сутність | Правило | Приклад | Неправильно |
|---|---|---|---|
| Клас | PascalCase | Medicine | medicine |
| Інтерфейс | I + PascalCase | IMedicineRepository | MedicineRepository |
| Метод | PascalCase | AddItem | additem |
| Властивість | PascalCase | UnitPrice | unitprice |
| Приватне поле | _ + camelCase | _items | Items |
| Локальна змінна | camelCase | totalPrice | TotalPrice |
| Константа | PascalCase | MaxQuantity | MAX_QUANTITY |
| Перелічення | PascalCase | PrescriptionStatus | prescription_status |

Назви повинні бути зрозумілими та відповідати призначенню елементів програми. Не рекомендується використовувати незрозумілі скорочення.

## 3. Форматування коду

У проєкті встановлено такі правила:

1. Для відступів використовуються 4 пробіли.
2. Табуляція для відступів не застосовується.
3. Довжина рядка не повинна перевищувати 100 символів.
4. Фігурні дужки розміщуються на новому рядку.
5. Фігурні дужки обов'язкові для умовних операторів і циклів.
6. Між членами класу залишають один порожній рядок.
7. Директиви using записуються на початку файлу.
8. Невикористані директиви using видаляються.
9. Кожен клас розміщується в окремому файлі.
10. Простори імен записуються у форматі namespace X;.

Ці правила допомагають підтримувати єдиний стиль написання коду.

## 4. Коментарі та документація

Коментарі використовуються лише тоді, коли необхідно пояснити складну дію або причину певного рішення.

Поганий приклад:

```csharp
// Додаємо одиницю
count++;
```

Кращий приклад:

```csharp
// Обмежуємо кількість відповідно до залишку на складі
quantity = Math.Min(quantity, stock);
```

Коментарі не повинні повторювати те, що вже зрозуміло з коду. Для публічних класів і методів бібліотеки надалі передбачається XML-документація.

## 5. Структура проєкту

Рішення PharmacyStock складається з двох основних проєктів.

**PharmacyStock.Core** містить класи предметної області та логіку роботи з ліками й рецептами.

**PharmacyStock.App** відповідає за запуск програми та виведення інформації в консоль.

Основні класи розміщуються в папці Domain. Логіка обчислень повинна знаходитися в бібліотеці Core, а не в консольному застосунку.

## 6. Правила комітів

Для контролю версій використовується Git.

Кожен коміт повинен описувати одну завершену зміну. Повідомлення комітів мають бути короткими та зрозумілими.

Використовуються такі типи:

- feat — додавання нових можливостей.
- fix — виправлення помилок.
- docs — зміни документації.
- chore — налаштування проєкту.
- style — форматування коду.

Приклад: `feat: додано моделі ліків і рецептів`.

Папки bin та obj не додаються до репозиторію.

## 7. Правила, закріплені машинно

Для автоматичної перевірки використовуються .editorconfig, Roslyn, StyleCop.Analyzers і dotnet format.

| Правило | Інструмент | Налаштування |
|---|---|---|
| Відступ 4 пробіли | .editorconfig | indent_size = 4 |
| Приватні поля з _ | Аналізатор іменування | IDE1006 |
| Обов'язкові дужки | .editorconfig | csharp_prefer_braces |
| Форматування пробілів | StyleCop | SA1028 |
| Порядок членів класу | StyleCop | SA1201 |
| Перевірка форматування | dotnet format | IDE0055 |

Правило SA1101 вимкнено, тому що в проєкті не вимагається використання префікса this. перед кожним звернення
