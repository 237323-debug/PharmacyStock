# Реєстр дефектів успадкованого модуля

Проєкт: PharmacyStock, варіант 19.
Файл: `src/Legacy/LegacyPrescriptionProcessor.cs`.
Номери рядків відповідають початковій версії, до рефакторингу.

| № | Дефект | Місце | Прояв | Рефакторинг |
|---|---|---|---|---|
| 1 | Довгий список параметрів | `Handle`, рядки 30-34 | 11 параметрів, частина описує одного пацієнта | Introduce Parameter Object |
| 2 | Довгий метод | `Handle`, рядки 30-114 | 80 значущих рядків, перевірка, розрахунок та звіт в одному методі | Extract Method |
| 3 | Вкладені умови | `Handle`, рядки 36-65 | 4 вкладені перевірки, порядок визначає код помилки | Decompose Conditional |
| 4 | Дублювання коду | `Handle`, рядки 73-92; `Preview`, рядки 124-142 | Повторюються три гілки знижок, обмеження 500 та доставка 60 | Extract Method, спільний розрахунок |
| 5 | Великий клас | `LegacyPrescriptionProcessor`, рядки 24-162 | Перевірка, сума, знижка, доставка, звіт, журнал, опис пацієнта | Extract Class |
| 6 | Одержимість елементарними типами | `Handle`, рядки 32-34, 40, 74-84 | Вид клієнта і стан документа передаються рядками `"vip"`, `"staff"`, `"new"` | Replace Primitive with Enum |
| 7 | Заздрість до чужих даних | `DescribeClient`, рядки 145-154 | Метод звертається тільки до полів `PatientRecord`, а не до стану процесора | Move Method |
| 8 | Тимчасове поле | `_tmpSum`, `_tmpDiscount`, рядки 26-27; використання 67-107 | Два поля зберігають проміжні результати лише для `Handle` | Remove Temporary Field |
| 9 | Магічні числа | `Handle`, рядки 74-92; `Preview`, 125-141 | 7 значень правил: `0.15m`, `0.30m`, `0.05m`, `500m`, `1000m`, `60m`, `10` | Replace Magic Number with Constant |

Окремо помічено параметри `clientId` і `createdAt`, які присутні в сигнатурі `Handle`, але не використовуються в тілі методу. Їх вилучення можливе лише під час подальшого рефакторингу публічного API із збереженням очікуваних результатів тестів.
